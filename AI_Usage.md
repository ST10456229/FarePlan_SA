## Specific Uses

### 1. Code Scaffolding

AI was used to generate **boilerplate code** for repetitive structures, including:

- **RecyclerView adapters** — `TripAdapter`, `ExpenseAdapter`, `ItineraryAdapter`, `SearchResultAdapter`. Each follows the same ViewHolder + `onBindViewHolder` pattern.
- **Data classes** — `Trip`, `Expense`, `ItineraryItem`, `UserProfile`. Simple Kotlin data classes with default values for Firestore compatibility.
- **Material Design layouts** — Activity XML files using Material 3 components like `TextInputLayout`, `MaterialCardView`, `BottomNavigationView`.
- **Firestore CRUD operations** — Read/write/update/delete operations following Firebase's API conventions.

**Value:** This saved several hours of typing and let me focus on the logic and UX rather than syntax.

### 2. Debugging and Error Resolution

AI was extensively used to diagnose build errors and runtime crashes. Notable examples:

- **Firebase KTX deprecation** — After Firebase BOM 34.0.0, the old `firebase-auth-ktx` module was removed. AI helped identify that imports needed to change from `com.google.firebase.auth.ktx.auth` to `com.google.firebase.auth.FirebaseAuth`.
- **Gradle compileSdk mismatch** — The error *"Dependency requires libraries that depend on it to compile against version 37 of the Android APIs"* was resolved with AI guidance on updating the `compileSdk` block.
- **RecyclerView inflation errors** — Diagnosed multiple layout XML errors (mismatched tags, wrong IDs, missing drawables).
- **Firebase Auth exception handling** — AI suggested using `FirebaseAuthException.errorCode` strings for cases like `ERROR_TOO_MANY_REQUESTS`, since Firebase does not provide a dedicated exception class for rate limiting.

**Value:** Reduced time spent on Stack Overflow searches; accelerated understanding of root causes.

### 3. Translation Drafting

AI drafted **isiZulu and Afrikaans** translations for all UI strings (~100 strings per language). These translations cover:

- Navigation labels (Home, Plan, Trips, Live, Budget)
- Form field hints (Email, Password, Destination, Budget)
- Button labels (Save, Cancel, Continue, Search)
- Error messages (Invalid credentials, No internet, Password too weak)
- Status indicators (Over budget, Daily budget)

**Limitation acknowledged:** These translations were generated by AI and have **not been validated by native speakers**. They may contain grammatical or cultural inaccuracies. For a production release, professional translation would be required.

### 4. Design Assets

AI generated **SVG vector path data** for icons used throughout the app, including:

- `ic_flight`, `ic_hotel`, `ic_car`, `ic_wallet` — category icons
- `ic_arrow_back`, `ic_menu`, `ic_search`, `ic_tune` — UI navigation
- `ic_calendar`, `ic_clock`, `ic_email`, `ic_lock`, `ic_person` — form field icons
- `ic_home`, `ic_plan`, `ic_trips`, `ic_map` — bottom navigation icons

Additionally, AI assisted in selecting the **colour palette** (teal primary `#2B9EB3`, navy `#1A2B4C`, orange accent `#F27A41`) to align with the FarePlan SA logo.

### 5. Documentation

AI assisted with:

- Structuring this `AI_USAGE.md` document
- Drafting the `README.md` project overview
- Formatting the demo video script

## What AI Did NOT Do

To be explicit about the boundaries:

- **Architecture decisions** — All decisions about data model design, navigation flow, feature prioritisation, and screen structure were made by the student.
- **Firebase configuration** — Project setup, security rules, Cloud Messaging configuration, and API key management were done manually via the Firebase Console.
- **API key management** — Obtaining and configuring the ExchangeRate-API key, and adding it securely to the project, was done by the student.
- **Testing strategy** — Unit test cases for `BudgetAlertHelperTest` and `CurrencyConverterTest` were designed by the student; AI assisted with JUnit syntax only.
- **Code review** — Every AI-generated function was read line-by-line and modified to fit the specific project context.
- **Debugging verification** — While AI suggested fixes, the student verified each fix by building and running the app.

## Reflection

### Benefits of AI Assistance

AI significantly accelerated the development process in three key ways:

1. **Reduced boilerplate time** — RecyclerView adapters, layouts, and Firestore CRUD operations were generated in minutes rather than hours.
2. **Faster debugging** — Errors that would have taken 30+ minutes to research on Stack Overflow were diagnosed in under 5 minutes.
3. **Consistent code style** — AI helped maintain consistent naming and structure across all files.

### Limitations Encountered

AI was **not always correct**. Notable examples:

- AI suggested a nonexistent class (`FirebaseAuthTooManyRequestsException`) that caused a build error requiring manual correction.
- AI occasionally generated code using deprecated Firebase APIs, requiring manual updates.
- AI-generated translations may not be culturally accurate.
- AI sometimes over-engineered solutions — simpler alternatives were often chosen after review.

### Overall Assessment

AI is a **productivity tool, not a replacement for understanding**. Every AI-assisted section of this project was reviewed, tested, and adapted. The student's own decisions about architecture, user experience, and testing strategy remain the foundation of the project.

The experience reinforced an important lesson: AI excels at *syntax and patterns*, but struggles with *context* and *correctness*. A developer who uses AI must still understand the code being produced to catch its mistakes.
